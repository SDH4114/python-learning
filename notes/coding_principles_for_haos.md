# Как научиться писать код правильно, гибко и без ошибок

Тебе нужно научиться не “писать код быстрее”, а думать как инженер:

```text
задача -> данные -> шаги -> функции -> проверки -> улучшение
```

Оптимизация приходит не от магии, а от правильного мышления.

## Главная формула хорошего кода

Перед кодом всегда спрашивай себя 5 вопросов:

1. Какие данные у меня есть?
2. Что я должен получить в конце?
3. Какие шаги между входом и выходом?
4. Какие ошибки могут случиться?
5. Что потом может измениться?

Если ты можешь ответить на эти вопросы, код уже будет лучше.

## 1. Сначала пиши просто, потом улучшай

Новички часто пытаются сразу написать “идеальный код”. Это ошибка.

Правильный путь:

```text
1. Сделай, чтобы работало
2. Сделай, чтобы не ломалось
3. Сделай, чтобы читалось
4. Сделай, чтобы было гибко
5. Только потом оптимизируй
```

Не начинай с оптимизации. Сначала добей правильность.

## 2. Думай не кодом, а данными

Перед функцией спрашивай:

```text
что функция получает?
что функция возвращает?
что она меняет?
```

Пример плохого мышления:

```text
“надо написать функцию”
```

Хорошее мышление:

```text
“функция получает список расходов и возвращает сумму”
```

Пример:

```python
def calculate_total(expenses):
    total = 0
    for expense in expenses:
        total += expense["amount"]
    return total
```

Это хорошая функция, потому что:

- понятно, что она делает
- она не спрашивает `input`
- она не печатает
- она возвращает результат
- её можно использовать где угодно

## 3. Разделяй 3 типа кода

В почти любой программе есть 3 слоя:

```text
1. Ввод/вывод
2. Логика
3. Сохранение данных
```

Например:

```text
input/print -> пользовательский интерфейс
calculate_total -> логика
save_json/load_json -> хранение
```

Плохой код смешивает всё:

```python
def calculate_total():
    expenses = input(...)
    print(...)
    save(...)
```

Хороший код разделяет:

```python
def calculate_total(expenses):
    return total
```

А `input`, `print`, `save` отдельно.

Это один из главных лайфхаков.

## 4. Хорошая функция делает одно дело

Если функция называется:

```python
add_student_and_grade_and_save_and_print()
```

значит она слишком большая.

Лучше:

```python
add_student()
add_grade()
save_students()
show_students()
```

Правило:

```text
если функцию трудно назвать коротко, она делает слишком много
```

## 5. Используй чистые функции

Чистая функция:

- получает данные
- возвращает результат
- не трогает внешние файлы
- не спрашивает `input`
- не печатает без причины

Пример:

```python
def get_average(grades):
    return sum(grades) / len(grades)
```

Такие функции легче тестировать, понимать и переиспользовать.

## 6. Сначала пиши алгоритм словами

Перед кодом напиши псевдокод:

```text
Для каждого ученика:
    собрать все его оценки
    посчитать средний балл
    если он больше текущего лучшего:
        сохранить этого ученика как лучшего
```

Потом превращаешь в Python.

Это сильнейший навык. Он учит думать, а не угадывать синтаксис.

## 7. Не оптимизируй раньше времени

Для твоего уровня главная оптимизация сейчас:

```text
не скорость, а ясность
```

Плохая оптимизация:

```text
хитрый код в одну строку, который ты сам завтра не поймёшь
```

Хорошая оптимизация:

- меньше повторов
- нормальные имена
- правильные структуры данных
- меньше вложенности
- функции делают одно дело

Быстрый код, который ты не понимаешь, бесполезен.

## 8. Выбирай правильную структуру данных

Очень часто “гибкость” зависит не от кода, а от данных.

Плохая структура:

```python
student1 = "Amin"
math1 = 90
physics1 = 80
```

Хорошая структура:

```python
students = {
    "Amin": {
        "math": [90],
        "physics": [80]
    }
}
```

Если данные хорошо организованы, код становится проще.

Лайфхак:

```text
если код становится слишком сложным, проверь структуру данных
```

## 9. Избегай глубокой вложенности

Плохой код:

```python
if user:
    if user["grades"]:
        if subject in user["grades"]:
            ...
```

Лучше:

```python
if not user:
    return

if not user["grades"]:
    return

if subject not in user["grades"]:
    return
```

Это называется early return. Код становится плоским и понятным.

## 10. Делай ошибки явными

Хороший код думает о плохих сценариях:

```text
а если список пустой?
а если файла нет?
а если ввели текст вместо числа?
а если такого ученика нет?
а если оценок нет?
```

Перед каждой функцией спрашивай:

```text
что может пойти не так?
```

## 11. Хорошие имена - это половина кода

Плохо:

```python
a = 0
b = []
x = {}
```

Хорошо:

```python
total_amount = 0
grades = []
students = {}
```

Если имена хорошие, код почти сам себя объясняет.

Правило:

```text
не экономь буквы в именах
```

## 12. Не повторяй код

Если ты пишешь один и тот же кусок 3 раза, почти всегда нужна функция.

Плохо:

```python
try:
    grade = int(input("> "))
except ValueError:
    ...
```

в 5 местах.

Лучше:

```python
def ask_number():
    ...
```

Но важно: не делай функцию слишком рано. Сначала увидь повтор, потом выноси.

## 13. Как придумывать хорошее решение

Используй схему:

```text
1. Самое простое решение
2. Какие у него проблемы?
3. Какую часть вынести в функцию?
4. Какие данные лучше хранить иначе?
5. Какие edge cases?
```

Пример:

Задача: найти лучшего ученика.

Самое простое:

```text
пройти по всем ученикам и сравнить средний балл
```

Проблемы:

```text
у ученика может не быть оценок
может быть несколько лучших
средний надо считать отдельно
```

Улучшение:

```text
отдельная функция calculate_student_average()
отдельная функция show_best_student()
```

## 14. Чеклист перед запуском кода

1. Все переменные названы понятно?
2. Функция делает одно дело?
3. Есть `return` там, где нужен результат?
4. Нет ли лишних глобальных переменных?
5. Что будет, если список пустой?
6. Что будет, если файл отсутствует?
7. Что будет, если пользователь ввёл мусор?
8. Нет ли повторения кода?
9. Можно ли эту функцию использовать в другом месте?
10. Я пойму этот код через неделю?

## 15. Как учиться быстрее

Лучший способ:

```text
проект -> ревью -> исправление -> второй ревью -> новый проект
```

То, что ты сейчас делаешь, идеально:

- написал Expense Tracker
- получил ревью
- исправил
- написал Student Analyzer
- получил ревью

Так растут быстрее, чем от бесконечных курсов.

## 16. Практика на ближайшие 2 недели

На каждом проекте тренируй 4 вещи:

```text
1. Чистые функции
2. Проверка ошибок
3. Хорошая структура данных
4. Разделение input/logic/save
```

Твои следующие мини-задачи:

- переписать одну старую функцию так, чтобы она не использовала `input`
- написать функцию, которая только считает и возвращает результат
- написать функцию, которая только печатает результат
- обработать пустые данные
- сделать один helper для безопасного ввода числа

## 17. Главное про оптимизацию

Есть 3 уровня оптимизации:

### Уровень 1: читаемость

```text
понятные имена
маленькие функции
нет повторов
```

Это сейчас самое важное.

### Уровень 2: алгоритм

```text
не делать лишние циклы
не пересчитывать одно и то же
использовать dict/set там, где нужен быстрый поиск
```

Пример:

```python
if name in students:
```

быстрее и чище, чем искать имя в списке циклом.

### Уровень 3: производительность

```text
NumPy
Pandas
vectorization
profiling
```

Это позже.

## 18. Самый важный лайфхак

Когда не знаешь, как писать правильно, делай так:

```text
1. Напиши рабочую тупую версию
2. Посмотри, где повторяется код
3. Вынеси повтор в функцию
4. Посмотри, где функция делает много дел
5. Раздели её
6. Добавь проверки ошибок
7. Переименуй переменные
```

Так почти любой плохой код становится нормальным.

## 19. Как понять, что решение хорошее

Хорошее решение:

- легко объяснить словами
- легко изменить
- легко проверить
- не ломается на пустых данных
- не зависит от случайных глобальных переменных
- функции короткие
- данные организованы понятно
- нет лишней магии

Если решение трудно объяснить, оно почти всегда плохое.

## 20. Главная мантра при кодинге

Перед каждой функцией:

```text
Что я получаю?
Что я возвращаю?
Что может сломаться?
Можно ли использовать это ещё раз?
```

Если будешь так думать, ты начнёшь писать код намного сильнее.
